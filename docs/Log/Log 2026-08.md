- 2026-08-23: two decisions inside that one worth keeping. **Tap order is tower, then build, then enemy, then clear** - building outranks inspecting because the Zero-Day sprite is 40px in a 32px trace and overhangs onto buildable tiles, so resolving enemies first would cost you a placement every time the boss walked past; enemies stay tappable over the trace, where nothing is placeable anyway. Hit radius is the sprite's larger half-side floored at a third of a tile, since a Packet Sniffer is 10x6 virtual pixels and is otherwise unhittable by a thumb.

- 2026-08-23: **the build menu now hugs the board's left edge instead of the window's** (user's call). The gap it closes is the letterbox: the world blits at an integer scale into a centered rect, so on most screens there is a black band between window edge and board edge, and a menu pinned to the window sits out in that band - further from the thing it builds on than it needs to be, which is the whole complaint. New `boardRect()` in `canvas.ts` turns the blit's device-pixel offset and scale into a CSS-pixel rect, since DOM chrome and the renderer had no shared unit before this.
- 2026-08-23: the placement rule is **split between JS and CSS on purpose, rather than computed whole in either.** JS publishes one number - the board-hugging candidate - as `--toolbar-left`; the floors stay in CSS as `max(8px, env(safe-area-inset-left), var(--toolbar-left, 0px))`. Doing it all in JS would have meant reading the safe-area inset from script, which `env()` does not expose to an unregistered custom property; doing it all in CSS would have meant knowing the toolbar's own width in a `left` calculation, where percentages resolve against the viewport rather than the element. Splitting it lets each side answer the part it can actually see, and `max()` is the whole arbitration: tuck into the letterbox when the band fits the menu, sit on the board's edge when it doesn't.
- 2026-08-23: known and accepted - **in portrait there is no side band to tuck into**, so the menu still overlaps the board's left edge there. A 16:9 board on a tall screen letterboxes vertically, and moving the menu into *that* band would mean an orientation-dependent layout, which is a bigger change than the complaint asked for. Landscape is where the game is 16:9 and where the band exists. Unverified by eye like everything else today: the extension is still disconnected, and this change is entirely about where a box lands on screen.
